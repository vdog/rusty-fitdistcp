# cibuildwheel test-venv constraints.
#
# The wheel's runtime dependency is `numpy>=1.22` (see pyproject.toml). On the
# manylinux2014 (glibc 2.17) test container, an unconstrained resolve picks the
# newest numpy, which no longer publishes a manylinux2014 cp312 wheel:
#
#   numpy <= 2.2.6  -> ships manylinux2014_x86_64 cp312 wheels (glibc 2.17)
#   numpy >= 2.3.0  -> dropped manylinux2014; only manylinux_2_28 (glibc 2.28)
#
# With no compatible binary wheel, pip falls back to building numpy from source,
# which fails the compiler check in the manylinux2014 image (GCC 10.2.1):
#
#   ../meson.build:25:4: ERROR: Problem encountered: NumPy requires GCC >= 10.3
#
# Pinning numpy to the last release that still ships a manylinux2014 cp312 wheel
# makes pip install a prebuilt binary instead of building from source, so the
# wheel test step succeeds on the old-glibc image.
#
# This constraint applies ONLY to the cibuildwheel test venv; it does not change
# the wheel's declared runtime dependency (`numpy>=1.22`), so end users still get
# the newest numpy their own platform supports.
numpy<2.3
